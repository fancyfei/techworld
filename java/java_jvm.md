# JVM 概述

## JVM的内涵

虚拟机（Virtual Machine）指通过软件模拟的计算机系统，在完全隔离的环境中提供完整的硬件功能。

JVM（Java Virtual Machine，Java 虚拟机）有两层含义：一是规范，定义了字节码格式、内存结构、类加载等行为；二是遵守该规范的软件实现，负责加载并执行已编译的 Java 字节码，运行在操作系统之上。

Java 的跨平台能力来自两个环节：编译器把源码编译成与平台无关的字节码，再由各平台的 JVM 把字节码转换为本地机器指令执行。Linux 和 Windows 的 JVM 实现不同，但遵守同一规范，因此同一份字节码可以在不同平台的 JVM 上运行。

## JVM 运行时数据区

运行时数据区是 JVM 的内存，负责存储运行期间的数据。规范把它划分为五个部分：

- 程序计数器：记录当前线程执行到的字节码位置。
- 虚拟机栈：方法执行时创建一个栈帧，存储局部变量、操作数栈等信息。
- 本地方法栈：为 Native 方法服务，作用与虚拟机栈类似。
- 堆：存放对象实例，是垃圾收集的主要区域。
- 方法区：存放类的元数据，如类结构、常量、静态变量。

规范只定义行为，具体实现随版本变化。最典型的是方法区：JDK 8 之前 HotSpot 用永久代实现，JDK 8 起改用本地内存中的元空间。

## 类的加载

类加载负责把 Class 文件读入运行时数据区，生成可用的类。类的生命周期分为加载、验证、准备、解析、初始化、使用、卸载七个阶段，其中验证、准备、解析合称链接。

JVM 内置三类类加载器，各负责不同来源的类：

| 类加载器 | 职责 |
| --- | --- |
| 启动类加载器（BootstrapClassLoader） | 加载 JDK 核心类库 |
| 扩展类加载器（ExtensionClassLoader） | JDK 8 及之前加载扩展目录中的类，JDK 9 引入模块化后被平台类加载器（PlatformClassLoader）取代 |
| 应用程序类加载器（AppClassLoader） | 加载类路径上的应用类 |

多个类加载器之间存在父子关系。一个加载器收到加载请求时先委派给父加载器，父加载器无法完成时才自己加载，这套流程称为双亲委派。结果是核心类库总是由上层加载器加载，应用代码无法替换它们。

## 字节码的执行

执行引擎读取 Class 文件中的字节码指令并逐条执行，输出结果。JVM 有一套独立于操作系统的字节码指令集，这是字节码能跨平台的前提。

Class 文件分两部分：元数据（类名、字段、方法签名等）和字节码指令集（方法体中的指令）。方法的执行以栈帧为单位：调用方法时栈帧入栈，方法返回时出栈，执行引擎运行的就是当前栈帧中的指令。

## 垃圾收集

垃圾收集（GC）负责回收不再使用的内存。堆和方法区的内存分配与回收是动态的，是垃圾收集的工作对象；程序计数器、虚拟机栈、本地方法栈三个区域随线程创建和销毁，由线程自行管理，不在收集范围内。

主流收集器以分代收集为基础：按对象存活周期把堆划分为新生代和老年代，对不同代采用不同的回收策略。

## 线程与内存模型

JVM 线程直接映射到操作系统线程。Windows 和 Linux 上的 HotSpot 使用一对一的线程模型，一条 Java 线程对应操作系统中的一条轻量级进程。

Java 内存模型（JMM）规定线程间如何共享数据：所有变量存于主内存，每个线程有自己的工作内存；线程只能读写自己工作内存中的数据，再与主内存同步。工作内存不是规范定义的具体存储区域，只是线程私有数据的抽象。

## 主流 JVM 实现

- HotSpot：OpenJDK 和 Oracle JDK 使用的虚拟机，最初由 Sun 开发，2006 年随 OpenJDK 开源；Oracle 收购 Sun 后把 JRockit 合并进 HotSpot。
- OpenJ9：IBM 开源的 JVM，高度模块化，启动开销低。
- Dalvik 与 ART：Android 平台的运行时。Dalvik 并非 Java 虚拟机，执行的是 dex 格式字节码；Android 5.0 起由 ART（Android Runtime）取代 Dalvik 成为默认运行时，以预先编译（AOT）替代 Dalvik 的即时编译（JIT）。

## JVM 上的其他语言

JVM 不只能跑 Java。任何能编译为 JVM 字节码的语言都可以在 JVM 上运行，并直接调用 Java 类库。常见的有：

- Kotlin：Android 官方支持语言。
- Scala：融合面向对象与函数式风格。
- Groovy：动态语言，Gradle 构建脚本的实现语言。
- Clojure：Lisp 方言，函数式。
