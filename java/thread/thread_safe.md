# 线程安全与锁实现

Brian Goetz 对线程安全的定义是：当多个线程访问一个对象时，如果不用考虑这些线程在运行时环境下的调度和交替执行，也不需要进行额外的同步，或者在调用方进行任何其他的协调操作，调用这个对象的行为都可以获得正确的结果，那这个对象是线程安全的。

在代码层面的要求是：代码本身封装了所有必要的正确性保障手段，调用者无需关心多线程的问题，也无需自己采取任何措施来保证多线程下的正确调用。

Java 代码可以自行实现线程安全，JVM 也提供了同步和锁机制。

## 多线程问题

多线程并发编程中通常会遇到三个问题：原子性问题、可见性问题、有序性问题。

- 原子性：一个操作或者多个操作，要么全部执行且执行过程不会被任何因素打断，要么就都不执行。
- 可见性：多个线程访问同一个变量时，一个线程修改了这个变量的值，其他线程能够立即看到修改后的值。
- 有序性：程序按照代码的先后顺序执行。

## Java 的线程安全程度

按照"安全程度"由强至弱排序，可以分为 5 类：不可变、绝对线程安全、相对线程安全、线程兼容、线程对立。

- 不可变：基本数据类型用 **final** 修饰；对象的行为不对自身状态产生任何影响，即可保证数据不可变。不可变的对象一定是线程安全的，这是最简单的实现方式。
- 绝对线程安全：要求在任何环境下调用者都不需要做额外的同步措施，实现成本高，Java 中较少见。
- 相对线程安全：保证对对象的单个操作是线程安全的，但复合操作（如先检查后执行）仍需调用者额外同步。java.util.concurrent 包下的类都属于这一级别。
- 线程兼容：对象本身不是线程安全的，需要调用端使用同步手段来保证线程安全。
- 线程对立：无论调用端是否采用同步措施，都无法在多线程环境下并发使用，Java 语言中基本不存在这类情况。

## 互斥同步实现线程安全

互斥同步（Mutual Exclusion & Synchronization）：多个线程并发访问共享数据时，用互斥保证共享数据在同一时刻只被一个或一些线程使用。

Java 中实现互斥同步主要有 synchronized 和 ReentrantLock 两种方式。

> 临界区（Critical Section）、互斥量（Mutex）和信号量（Semaphore）都是主要的互斥实现方式。

### synchronized

Java 中最基本的互斥同步手段是 synchronized 关键字。该关键字经过编译后，会在同步块的前后分别形成 monitorenter 和 monitorexit 两条字节码指令，二者都需要一个 reference 类型的参数来指明要锁定和解锁的对象。

执行 monitorenter 时，先尝试获取对象的锁：获取成功，锁计数器加 1；获取失败，当前线程阻塞等待，直到对象锁被释放。

执行 monitorexit 时就将对象的锁计数器减 1，计数器减到 0 时，锁被释放。

synchronized 的重量级路径依赖操作系统的互斥原语（Mutex），获取失败会涉及用户态到内核态的转换，开销较大；JDK 6 起引入了偏向锁、轻量级锁和自适应自旋等优化，减少重量级锁的使用频率。

> synchronized 的 reference 参数可以直接指定。
>
> 如果 synchronized 修饰的是实例方法，reference 参数就是 this。
>
> 如果修饰的是类方法，reference 参数就是此类的 class 对象。

### ReentrantLock

除了 synchronized，还可以使用 java.util.concurrent 包中的重入锁（ReentrantLock）实现同步。它是 API 层面的互斥锁，通过 lock、unlock 配合 try-finally 使用。与 synchronized 相比，它提供了等待可中断、公平锁、绑定多个条件等高级功能，但这些功能并不意味着性能更强。

## 非阻塞同步实现线程安全

非阻塞同步（Non-Blocking Synchronization）基于冲突检测的乐观并发策略：先进行操作，如果没有其他线程争用共享数据，操作成功；如果产生冲突，再采取补偿措施（如重试）。这种方式性能更好，但需要硬件指令集支持：

- 测试并设置（Test and Set）
- 获取并增加（Fetch and Increment）
- 交换（Swap）
- 比较并交换（Compare and Swap，CAS）
- 加载链接、条件存储（Load Linked / Store Conditional，LL/SC）

其中 CAS 由 sun.misc.Unsafe 类的 compareAndSwapInt、compareAndSwapLong 等方法包装提供，由 JVM 特殊处理；java.util.concurrent 包的整数原子类就是基于 Unsafe 的 CAS 实现的。

CAS 需要 3 个操作数：内存位置（变量的内存地址 V）、旧预期值（A）、新值（B）。执行时，当且仅当 V 的值符合 A，就用 B 更新 V，否则不更新；无论是否更新，都会返回 V 的旧值。上述处理过程是原子操作。

## 代码实现线程安全

让一个方法不涉及共享数据，就无需任何同步措施。有两类代码天生线程安全：可重入代码和线程本地存储。

- 可重入代码（Reentrant Code）：不依赖堆上的共享数据和公用的系统资源，状态全部由参数传入，也不调用非可重入方法。满足这些条件的代码可以在任意线程中安全执行，且返回结果可预测。
- 线程本地存储（Thread Local Storage）：如果共享数据能在同一线程内完成处理，可以将数据放入 java.lang.ThreadLocal，实现线程封闭（Thread Confinement）——每个线程只能访问自己的数据副本，从代码层面保证了线程安全。
