# JVM 的方法调用

方法调用阶段的唯一任务是确定被调用方法的版本（即调用哪一个方法），不涉及方法内部的执行过程。Class 文件中的方法调用目标一律以常量池中的符号引用表示，确定目标方法有两条路径：解析和分派。

## 方法调用字节码指令

JVM 一共提供 5 条方法调用指令：

| 指令 | 调用目标 |
| --- | --- |
| `invokestatic` | 静态方法 |
| `invokespecial` | 实例构造器 `<init>` 方法、私有方法、父类方法 |
| `invokevirtual` | 虚方法 |
| `invokeinterface` | 接口方法，运行时再确定一个实现该接口的对象 |
| `invokedynamic` | 先在运行时动态解析出调用点限定符所引用的方法，再执行该方法 |

## 解析调用

解析调用指在类加载的解析阶段就把一部分符号引用转为直接引用，即在编译期就能确定唯一的目标方法。满足这一条件的方法包括：

- 静态方法
- 私有方法
- 实例构造器 `<init>` 方法
- 父类方法
- 被 `final` 修饰的方法（虽由 `invokevirtual` 指令调用，但因不可重写而属于非虚方法）

## 分派调用

分派调用与重载、重写特性相关，可能是静态的，也可能是动态的。

### 静态分派与重载

静态分派发生在编译期，典型应用是方法重载：编译器根据参数的静态类型（声明类型）而非实际类型来确定方法的执行版本。

### 动态分派与重写

动态分派发生在运行期，典型应用是方法重写：JVM 根据接收者变量的实际类型确定方法的执行版本，这是 Java 多态的实现基础。

### 单分派与多分派

按分派依据的宗量个数，分派又可分为单分派和多分派（方法的接收者与方法的参数统称为宗量）：

- 单分派：依据一个宗量即可确定调用目标。
- 多分派：需要依据多个宗量才能确定调用目标。

按这个标准，Java 语言是一门静态多分派、动态单分派的语言：静态分派时接收者和参数的静态类型都是待选的宗量，需同时参与选择；到动态分派时参数类型已在编译期固定，只剩接收者的实际类型一个宗量。

## invokedynamic 指令

`invokedynamic` 随 JDK 7（JSR 292）引入，把方法分派的控制权从 JVM 固定逻辑交还给语言实现者；JDK 8 起 Java 自身的 Lambda 表达式也编译为 `invokedynamic` 调用。

使用 `invokedynamic` 的类，其常量池中会出现 `CONSTANT_InvokeDynamic` 类型的常量项，其中记录了调用点的方法名、方法描述符，并引用一个引导方法（Bootstrap Method，BSM）。

`invokedynamic` 的调用点（Call Site）在类加载时是未链接的（unlinked）。指令首次执行时，JVM 调用引导方法，由它决定具体调用的方法并返回一个 `CallSite` 对象；该对象与调用点完成绑定后，后续执行直接调用其中缓存的方法句柄，不再重复调用引导方法。

方法句柄（Method Handle）是 JSR 292 在 `java.lang.invoke` 包中引入的机制，定位类似反射，但由 JVM 直接提供支持，调用开销更小，与 `invokedynamic` 一起构成了 Java 的动态方法调用能力。
